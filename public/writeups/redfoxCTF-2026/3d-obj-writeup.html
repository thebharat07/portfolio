Challenge Description

The challenge lore read:

"Kratos used the Jotnar powers of prophecy to see into the future and observe how humanity was going to turn out. He was shell shocked, but amused. Can you spot what his reaction was?"

We were given a single file: TheNewAge with no file extension. The task was to figure out what was inside it and identify Kratos' reaction.

Step 1 — File Identification

The first step with any unknown file in a CTF is to run the file command. Never assume a file is what it looks like — file extensions lie, but magic bytes don't.

bash 
file TheNewAge

Output:

output 
TheNewAge: ASCII text, with very long lines (65536), with no line terminators
⚡ Key Observation

65536 characters in a single line with no terminators is extremely suspicious. This is a classic sign of encoded binary data — likely base64 or hex. The character count (65536 = 2^16) is also a power of 2, which is a hint.

We checked the first few characters to determine the encoding:

bash 
# Check first 100 characters
head -c 100 TheNewAge

Output:

23204f626a656374204578706f72742046726f6d2054696e6b65726361642053657276657220323031350a0a6d746c6c6962...

All characters were in the range 0-9 and a-f — this is hexadecimal encoding. Two hex characters represent one byte, so 65536 hex chars = 32768 bytes of actual data.

Step 2 — Hex Decode

We decoded the hex data to a binary file using Python's xxd or a quick Python one-liner:

bash 
# Method 1: using xxd
cat TheNewAge | xxd -r -p > TheNewAge_decoded

# Method 2: using Python
python3 -c "import binascii; open('decoded','wb').write(binascii.unhexlify(open('TheNewAge').read().strip()))"

# Check what we got
file TheNewAge_decoded

Output:

output 
TheNewAge_decoded: ASCII text

Step 3 — Identify the Decoded Content

The decoded file was ASCII text. We read the first few lines to identify the format:

bash 
head -20 TheNewAge_decoded

Output:

⚡ Key Discovery

The first line reveals everything: "# Object Export From Tinkercad Server 2015" — this is a Wavefront OBJ file exported from Tinkercad, a popular 3D design tool. The v lines are 3D vertices (x, y, z coordinates).

What is a Wavefront OBJ file?

📍
v x y z
Vertex — a point in 3D space defined by x, y, z coordinates.
🔺
f v1 v2 v3
Face — connects vertices to form a polygon (triangle or quad).
📐
vn x y z
Vertex normal — defines the direction a surface faces for lighting.
🏷️
o name
Object name — groups geometry into named objects within the file.

Step 4 — Rename and Render in 3D Viewer

We renamed the decoded file with the .obj extension so 3D viewers would recognize it:

bash 
cp TheNewAge_decoded TheNewAge.obj

Then uploaded it to an online 3D viewer. We used 3dviewer.net — a free web-based OBJ viewer that requires no installation:

Tools for viewing OBJ files: 3dviewer.net (web, free), Blender (desktop, free), MeshLab (desktop, free), Autodesk Viewer (web), or simply drag-and-drop into Windows 3D Viewer.

Step 5 — The Reveal

Opening the OBJ file in the 3D viewer revealed the model clearly — a golfer figure: a person wearing a flat cap, dressed in flared trousers, and firmly gripping a golf club. However, the true discovery was not the man himself, but what stood etched in the digital void next to him. Floating beside the figure, rendered in sharp 3D text, was the secret the giants had hidden.

Once you know the technique, the entire decode can be done in a single command:

cat TheNewAge | xxd -r -p > solution.obj && file solution.obj && head -3 solution.obj

Key Lessons

1. Always Run file First

Never trust the filename or extension. The file command reads the actual content (magic bytes and structure) to determine the true file type. This is the first command to run on any unknown file in a forensics challenge.

2. Long Single-Line ASCII = Encoded Data

A file that is all ASCII but has no newlines and is very long is almost always encoded binary data. The most common encodings are base64 (uses A-Z, a-z, 0-9, +, /) and hex (only 0-9, a-f). Check the character set to determine which one.

quick identification cheatsheet 
# Characters only 0-9 and a-f (or A-F) → HEX encoding
# Characters A-Z, a-z, 0-9, +, / and ends with = → BASE64
# Starts with eyJ → Base64-encoded JSON (likely JWT)
# Characters only 0 and 1 → BINARY encoding
# Printable ASCII with structure → direct text format

# Quick check for hex vs base64:
head -c 20 file | grep -P '^[0-9a-fA-F]+$' && echo "HEX" || echo "Not pure hex"

3. Check the First Line for Format Clues

Many file formats embed human-readable identifiers in their first line or as comments. The OBJ format starts with # comment lines. Always read the first few lines of decoded data — they often immediately tell you what format you're dealing with.

4. Visual Challenges Require Visual Tools

Once we identified the OBJ format, trying to read vertex coordinates manually would have been futile. The correct approach is always to use the right tool for the format — a 3D viewer for 3D models, an image viewer for images, a hex editor for binary, and so on.

5. Power of 2 File Sizes Are a Hint

65536 characters is exactly 2^16. When you see file sizes or lengths that are powers of 2, it often signals encoding or padding — worth noting as a clue during initial analysis.
